# circuit-breaker

服务网格场景下的熔断器（Circuit Breaker）状态机，仅使用 Go 标准库实现：
关闭（Closed）/ 打开（Open）/ 半开（HalfOpen）三态流转，基于滑动时间窗口的
增量错误率统计与半开态探测限流。每个实例独立统计、独立流转，互不影响。

## 状态机转换规则

```
          窗口内请求数 >= MinRequests
          且错误率 >= ErrorThreshold
   Closed ──────────────────────────► Open
     ▲                                  │
     │                                  │ now >= openedAt + Cooldown
     │                                  ▼（边界含于半开侧）
     │   连续 SuccessThreshold        HalfOpen
     └────────── 个探测成功 ◄────────────┘
                    任一探测失败 ──► 回到 Open，
                                    冷却计时从失败时刻重新起算
```

| 转换 | 触发条件 |
|---|---|
| Closed → Open | 窗口内请求总数 ≥ `MinRequests` **且** 错误率 ≥ `ErrorThreshold` |
| Open → HalfOpen | 当前时间 ≥ `openedAt + Cooldown`（冷却期满，**含边界时刻**） |
| HalfOpen → Open | 任一探测请求失败，`openedAt` 重置为该失败时刻 |
| HalfOpen → Closed | 连续 `SuccessThreshold` 个探测成功 |

**边界一致性**：打开→半开的判定是 `(now, openedAt, Cooldown)` 的纯函数
（`now >= openedAt + Cooldown`），同一时刻无论判定多少次、从 `Allow` 还是
`Snapshot` 进入，结果都一致，不会出现同一时刻两种状态判定。

**最小样本数门控**：窗口内请求总数低于 `MinRequests` 时，即使错误率 100%
也不打开，避免低流量下单次失败误触发。

## 滑动窗口统计算法

窗口被划分为 `Buckets` 个等长分桶（环形缓冲），每个分桶记录落在其中的
请求总数与失败数；窗口整体维护 `total` / `failures` 两个滚动计数：

- **写入**：对齐到当前分桶后增量累加，O(1)；
- **淘汰**：时间前进时，把滑出窗口的分桶计数从滚动值中**增量扣除**并清零，
  均摊 O(1)，不做全量重算；
- **语义**：任意时刻窗口覆盖分桶下标区间 `[cur-n+1, cur]`，与"对原始事件
  按同一分桶下标过滤后全量求和"严格等价（测试逐步比对验证）；
- 时间回退时统计保持单调，不倒退。

## 半开态探测限流

- 半开态最多同时放行 `MaxProbes` 个探测请求，超出配额的请求直接拒绝，
  防止积压请求同时涌入下游；配额计数由互斥锁保护，并发竞争下不超发。
- 任一探测失败**立即**回到打开态，冷却计时从该失败时刻重新起算。
- 连续 `SuccessThreshold` 个探测成功才完全关闭，并重置窗口统计。
- **过期许可隔离**：每次状态切换递增代际号，`Permit` 携带代际；状态切换后
  迟到的上报（如上一轮半开探测的迟到结果）被直接丢弃，不污染新一代际的
  统计与关闭进度。

## 多实例

`New(cfg, clock)` 创建的每个实例持有完全独立的状态（窗口、代际、配额、
冷却计时），不共享任何变量，可安全用于服务网格中按下游/按路由维度各建
一个熔断器的部署方式。

## API 概览

```go
cb := breaker.New(breaker.DefaultConfig(), nil) // nil 使用系统时钟
p, ok := cb.Allow()        // 请求许可
if !ok { /* 快速失败 */ }
cb.Report(p, err == nil)   // 上报结果
// 或使用便捷封装：
err := cb.Do(func() error { return callDownstream() })
snap := cb.Snapshot()      // 可观测状态（含有效状态、窗口计数、错误率）
```

测试与回放通过注入 `ManualClock` 获得确定性时间，精确复现冷却边界时刻。

## 测试

```sh
go test -race ./...
```

覆盖：

- 滑动窗口增量统计与全量重算逐步一致（随机事件流 2000+ 步比对）、分桶淘汰、时钟回退；
- 最小样本数门控避免低流量误触发；错误率阈值触发；
- 半开态探测配额在 64 协程并发竞争下不超发（`-race`）、多次打开-半开循环配额稳定；
- 半开态任一失败立即回退且冷却重置；连续成功阈值关闭；
- 冷却边界时刻（±1ns）状态判定一致性、同一时刻重复判定一致；
- 跨代际过期许可被忽略；多实例状态独立互不影响。

## 可视化回放

```sh
go run ./cmd/genreport          # 生成 report.html
open report.html                # 浏览器打开即可，无需任何服务
```

生成单一静态 HTML（数据与逻辑全部内嵌，原生 HTML/CSS/JS，无第三方库），
逐帧回放一段完整调用序列：健康流量 → 故障风暴触发打开 → 冷却边界精确探测
→ 半开并发探测配额竞争 → 探测失败回退并重置冷却 → 连续成功关闭 → 低流量
单次失败被门控。支持播放/暂停/逐帧/变速/进度拖动，状态切换时刻在时间线
与错误率曲线上高亮。
